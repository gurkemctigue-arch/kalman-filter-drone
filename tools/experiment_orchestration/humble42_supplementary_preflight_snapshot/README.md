# 补充检测证据前置校验工具快照

本目录保存经过独立审查的外部工具、合成测试、交接说明和小型审查记录。原件按字节复制，文件大小、原路径和 SHA256 见 `snapshot_manifest.json`。本目录不包含实际实验协议、补充绑定合同或正式飞行准入文件，也不表示正式实验已经开始或项目验收通过。

## 用途与接口

原有正式实验串行工具只绑定原准入文件，不检查新增的补充检测协议和选源清单。本工具放在它的 `--guard-command` 前缀中，在委托原适配器之前检查这些小型元数据的实际路径、内容摘要、时间顺序和历史记录。

| 动作 | 行为 |
| --- | --- |
| `describe`（默认） | 输出工具身份；不启动实验、不创建记录 |
| `verify` | 显式检查真实绑定；不写入审计或原始实验记录 |
| `run-one` | 检查通过后追加独立外部审计，再以 `exec` 委托原适配器 |

工具不创建协议、计划或准入，不选择或重试实验槽，不改动原 guard，不读取录包或权重，不执行整树哈希、推理或仿真。成功委托前不增加标准输出装饰；原适配器负责原有输出、退出、信号处理和运行期管理。具体命令形态及 12 字段绑定结构见 [handoff01](formal_supplementary_preflight_handoff01.md)，其中所有 `ACTUAL_*` 均为占位符，不能当作真实参数执行。

## 首次与后续执行

首次校验必须发生在原 `initial_admission.json` 产生以前，且原 280 槽的试验目录、开始标记和终态均不存在。工具仅在新的外部 JSONL 中留下事前检查证据；原适配器与 guard 随后仍负责原准入和飞行。

后续校验允许原槽已经开始、完成或失败，但必须保留最初的审计，且它早于原始初次准入和开始记录。缺失的事前证据不能在试验后补造。审计表示“已完成这次前置检查”，不表示适配器或飞行完成。保持一个原有串行调度者和一个写入者；该审计不是新的运行锁或进程管理器。

## 实际执行顺序

1. 按原门槛完成开发核心、安全、扩展、容量证据、定标、独立最终根构建和注册。
2. 生成实际 FORMAL120 与 EXTENSION_FORMAL160，完成绑定真实正式计划的 replay 注册，全部 280 槽仍未尝试。
3. 在首次正式尝试以前，生成真实外部补充检测协议，保留原选源、依据及已批准审查记录的实际摘要。
4. 完成原最终源封存、整树事前校验和完整 280 槽容量封存，取得实际原准入文件。
5. 此时才创建并独立检查补充绑定合同，保存实际 SHA；显式 `verify` 后，通过原串行工具委托运行。原 guard 的准入、容量、锁和槽选择规则继续生效。

协议、绑定合同和新审计必须在整个最终冻结源根及其真实 results 目标以外，使用外部全新路径。容量预算需覆盖原两条检测子集、新增固定 12 条来源的无截断完整抽样、图像、无预测标签叠图、审核、缓存和时延输出。固定 12 条复用既定 person/car × 六组 × seed1000 来源，不新增飞行，完整工程分母仍为 280。

## 依赖与归档边界

本目录是源码归档，不能单独部署。外部工具原件仍位于 `D:/WSL/UAVHumble22-validation`；真实 Linux 执行需使用实际物理路径，并保留原适配器等要求的同目录依赖。快照没有改写这些绝对路径约定。实际运行依赖以下原有内容：

- [Humble41 快照](../humble41_snapshot/README.md)中的原适配器、原串行器和运行期管理工具，以及最终源内的原 guard。
- [Humble42 快照](../humble42_snapshot/README.md)和[最终根连接快照](../humble42_final_connection_snapshot/README.md)中的原开发门槛、最终根与封存流程。
- [补充检测工具快照](../../offline_evaluation/prospective_detection_v1/README.md)中的已审生产工具和原检测独审记录。
- 真正安装并验证过的仿真环境、模型、完整原始证据、实际注册、正式计划、源封存、容量准入和选源文件。

测试源码也保留原件依赖布局，不承诺从本快照目录直接运行即可通过。清单列出了关键依赖的仓库位置和摘要，未把运行环境或真实数据打包进来。

随附的 `humble42_postcore_safety_readonly_checklist01.md` 和 `humble42_postsafety_extension_readonly_checklist01.md` 是当时形成的只读后续流程备忘录，不是实时进度，也不替代实际门槛或原始结果。原审查 JSON 中的绝对路径保留其历史来源；已收录的小日志仅为本工具的合成测试输出。无录包、视频、模型权重、账号信息、机器运行日志或真实准入产物。

后续实际检测抽样、无预测图像审核、推理、评价、报告语义验证和时延分析，仍须在原录制结束及资源空闲后按各自工具执行。计划书和报告只能引用真实生成并审核过的结果。
