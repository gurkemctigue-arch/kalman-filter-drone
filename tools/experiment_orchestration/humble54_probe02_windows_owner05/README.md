# Prepared Windows owner 05

This is an unregistered template copied from the held-handle owner04 source.
Production remains disabled; gate, chain-validator and registered-profile
hashes are `None`. There is no launch profile or actual closed-prefix instance.
Calling default mode only reports this state; `--execute` refuses without
starting any process.

The template preserves creation-bound Windows handles, kernel exit/Popen.wait
cross-checks, immutable first-exit observations, early Linux owner identity,
the temporary system/display power request and waiting for owned commands on
publication or validation faults. It uses fresh owner05/monitor/receipt paths
and never resumes an old owner directory.

The new native command targets the independent registered05 gate. The original
prepared collector source is separately pinned and remains the source recorded
by its native `state.json`. The outer additionally binds the gate's fresh
admission (profile, chain validator, prepared collector and Linux identity)
during actual lifetime and verifies its exact raw hash against the final gate
terminal and native collector terminal after the held processes exit.

There is no assumption that this owner executed the original closed prefix.
Its monitor sees the collector's explicit derived-prefix observations separately
from actual pending child invocations. Completed collection is not engineering
acceptance. STOPPED_FAULT can have verified process closure and still returns 2.

No WSL call, flight, group/child signal, real launch or profile registration was
performed while preparing this source. Root must register and review the actual
gate/profile/chain/source pins after prior-owner closure before execution.
