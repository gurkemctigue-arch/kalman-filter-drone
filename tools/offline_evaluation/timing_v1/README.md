# 离线可观测时延工具源码快照 v1

本目录保存已独立审查的离线分析组件。它帮助区分录包接收时钟、ROS 源时钟和本地耗时，保留缺失、冲突及未知样本。它不改变在线跟踪/控制、冻结 42、既有试验或验收结果。

本快照中的 **45 项作者测试**分别在 Windows Python 3.12、Ubuntu 22.04/Humble Python 3.10 通过；独立审查在 Windows 复跑作者测试并加入 3 项独立对抗测试，合计 **48 项通过**。两者均为使用临时合成数据的组件测试，包括完全模拟的原生读取器；它们不代表飞行试验、真实 ROS 消息 ABI 验证或项目可靠性达标。此次快照整理没有重跑这些测试。

**尚未产生实际时延测量。** 未读取实际 bag、原始运行日志、图像或权重，未启动实际推理、仿真或正式实验。实际 worker 墙时 FPS、图像采集到控制器/PX4/执行结果的因果端到端时延仍为 `NOT_OBSERVED`。不得把录包接收速率当成物理 FPS，也不得跨时间域相减或使用 RTF 推算时延。

- `snapshot_manifest.json` 记录每个复制文件的原路径、字节数、SHA-256，以及本地说明文件的字节数和 SHA-256。清单不递归绑定自身，其 SHA 由交接时另行提供。
- 局部 `.gitattributes` 使用 `* -text`，用于保持本目录原始字节，不对已审查文件进行换行转换。
- 被接受的工具 manifest canonical SHA-256 为 `5050ed369c680fd6b7c746fc7481b0635fd6aaebf2159e4ffc6d1b6bef4faeee`。
- 独立审查回执 SHA-256 为 `b966a3cf167acecc15e09ea21a8180d48dbd87c228acfc38b294f95d4f10d3e2`，结论范围为源码和合成夹具。

回执仍引用原验证目录中的小型测试输出日志及作者回执生成脚本；**这些 3 份测试日志和作者生成脚本没有收入本快照**。`snapshot_manifest.json` 显式列出缺项及回执中已记录的 SHA，不能仅凭本目录重新校验这些未附文件。原回执中的 Windows/WSL 绝对路径是历史来源说明，克隆仓库后不会自动变成有效本地路径。源码和已附回执可通过本目录清单独立校验；完整原测试日志仍由原验证归档保存。

## 安全查看与可选组件复验

在本目录执行以下命令只描述组件，不执行实际导出：

```bash
python -B offline_pipeline_timing.py describe
```

如需重新检查组件，可在本目录手动运行标准库合成测试；无需安装 ROS 或读取实际录制数据：

```bash
python -B -m unittest -v test_offline_pipeline_timing test_offline_pipeline_timing_independent01
```

重新运行得到的是新的本机组件测试结果，不会替代所附原回执。GitHub 源码快照不是已经运行过的实际测量报告。

## 实际测量的前置条件

实际 `export` 和 `analyze` 必须由主流程在资源独占窗口显式安排，并使用经批准的、已停止写入的原始数据。必须明确提供原冻结源码根、原试验录制目录、实际原实验计划输出保护根（至少一个 `--protected-root`）、所选原始小日志以及全新的外部输出路径。原冻结源码/试验/计划输出不可写入；`results` 的符号链接目标也受保护。压缩 bag 的原读取器可能需要额外解压临时空间。

导出与分析须在同一路径环境进行，核对实际原源码/消息环境、原录制完整性和导出的 context SHA。分析会重新解析所有绑定的原始小日志，与规范化 job 事件逐项核对；无日志支持、缺漏、追加、改动或顺序不符都不能成为已知时序样本。同一物理日志行发生冲突时，全部相关机会保留为未知。完整读到录制末端不等于通过录制尾部或飞行验收。

完整边界及占位命令见 `offline_pipeline_timing_handoff02.md`。其中的原验证目录和示例路径仅说明原来源/接口，实际运行应替换为本机明确批准的输入。未包含 bag、模型权重、真实运行日志、认证信息或实际测量输出。快照本身不启动任何生产动作，也不更新实验 PASS/FAIL 或正式种子账本。
