日期：2026-10-29。用户已授权制定详细计划后直接开始实施。此计划覆盖汽车可靠性、跟随距离/高度、主动云台、指定个体证据、基础设施与复现环境；不扩展到完整 ReID、搜索、避障或真实飞行。

## 目标与判断标准

交付可运行的改进版本、可解释的失败诊断及独立验证记录。原 v3 的 166 主槽、16 扩展槽、所有失败和不完整证据原样保留。新结果与 v3 分组比较，不能覆盖、重命名或改判历史试验。不会承诺靠修复使任意场景全部成功，也不预设自适应 KF 必须优于所有基线。

必须保持：运行时不读取实体名称/真值；指定个体不自动替换；LOST 后须显式重选；观测 0.60 s、预测 0.75 s 和 PX4 安全门不因试验失败而放宽；位置和速度设定值互斥。一次只运行一个仿真或重型离线任务。

## 决策与默认值

- 先在已验证的 Ubuntu 24.04/Jazzy 环境修复和验证，再单独处理 Ubuntu 22.04/Humble 兼容；不混装 ROS 包。
- 架构保持传感器、估计、目标管理、控制和适配器边界；优先更正测量/时间契约，随后调整有证据支持的控制参数。
- 所有新诊断使用 `reliability_v4` 前缀和唯一试验名。开发探针可逐修订执行，最终验证冻结后只执行预登记槽。
- 身份 unknown 只在独立可观察/审核证据支持时消解，不把 unknown 改成 correct；完全不可见时继续记 unknown。
- 不以“调低遮挡时长、移除失败段、降低验收门槛、只保留 PASS”解决问题。

## 工作顺序与验收关口

1. **证据审计和问题复现。** 并行检查控制/锚点、检测/时序/KF、云台/身份三条链。记录具体源码行、参数和样本时序；必要时在空闲窗口只读解包一个有明确问题的 bag。交付原因矩阵，标注已证实与待验证假设。
2. **可观察性和确定性回归。** 记录接受/拒绝观测、创新、R/P、马氏距离、采集/接收/推理/TF 等诊断；只对存在证据的缺陷写回归。先保证问题能复现，禁止仅加镜像实现的测试。
3. **测量与闭环修复。** 根据审计修复 RGB-D 鲁棒锚点、视角/运动补偿、测量队列和控制参考；保留原视觉锚点指标，并增加与实际控制目标一致的独立指标。云台修复与身份保护一并验证，不以图像中心误差单独验收。
4. **逐项开发探针。** 在独立可变工作区构建四个 ROS 包，核验导入隔离。先行人/汽车无故障，再短长遮挡与重选，再 active/midpoint、多目标交叉、故障与距离。每次保留 bag、参数、源码/模型哈希、完整评价、失败与进程退出记录。
5. **冻结新版本并独立重复。** 先登记源码、配置、种子、指标和分母。沿用可比较条件，关键类别/控制/云台/交叉条件至少 10 个独立种子，配对报告全可测与双方 PASS 子集；扩展每条件一次与十次重复分开。最终失败不得自动重试，基础设施停止先诊断再推进未执行槽。
6. **修复证据与环境边界。** 历史缺失证据能从原始内容恢复时另存衍生审计，保留原 FAIL/缺失；无法恢复时明确原因。资源允许时新建隔离 Ubuntu 22.04/Humble 环境，检查核心测试、colcon、消息版本、桥接和 SITL；未实际通过的组合不能宣称验证。
7. **交付与同步。** 完成相关/全套测试、真实退出清理检查、图表/指标/视频/Word/PDF 和统一验收页。报告“哪些问题已修复、哪些仍失败、证据局限”，同步已授权 GitHub 仓库 `kalman-filter-drone`。

每关失败时保留结果，在同一范围内修正并使用新开发探针名；若需改变身份定义、引入完整 ReID、实机或其他新范围，再询问用户。日常实现取舍由代理处理，不因已有授权的构建/仿真反复请求确认。
