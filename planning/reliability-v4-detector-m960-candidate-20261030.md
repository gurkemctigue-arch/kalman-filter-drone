# YOLO11m/960 的追加开发候选

本候选基于已经完成的离线对照提出，须在新推理前固定方案。它只检查同一开发图像上的检测框，不改变当前运行模型，不消耗正式种子，也不表示已经选择 YOLO11m/960。原 Humble25 失败、所有旧推理输出、评分失败收据、原图和标签继续保留。

## 提出依据

已完成的固定阈值检测结果如下，三项依次为 TP / FP / FN：

| 候选 | crossing：93 帧、279 框 | multi：44 帧、132 框 |
| --- | --- | --- |
| YOLO11s/640 | 275 / 12 / 4 | 112 / 7 / 20 |
| YOLO11m/640 | 267 / 0 / 12 | 96 / 0 / 36 |
| YOLO11s/960 | 274 / 20 / 5 | 129 / 7 / 3 |
| YOLO11s-seg/640，仅评价框 | 226 / 0 / 53 | 100 / 0 / 32 |

第二轮评分文件 SHA-256 为 `2afa7246ef7c43225150b7de6f25606db78d598c8884096211a061c1451efc42`。YOLO11s/960 在 multi 的中央 `stage2_car_0` 重选后窗口得到 22 TP、1 FN，前后正确匹配间隔为 0.2 秒，但仍有局部额外框；YOLO11m/640 去除了本组假阳性，却增加小车漏检。追加 YOLO11m/960 用于检验提高输入尺寸是否能补回 m 模型的小车测量，同时保留其局部额外框表现。该推断还没有得到 m/960 结果支持。分割候选在本组漏检较多，当前不采用。

## 在新推理前固定的唯一候选

- 权重：现有官方 `yolo11m.pt`，SHA-256 `d5ffc1a674953a08e11a8d21e022781b1b23a19b730afc309290bd9fb5305b95`。
- 模型任务：`detect`；`imgsz=960`，`rect=True`，实际 forward 输入必须为 `[1, 3, 736, 960]`。原图仍为 640×480，评价框使用原图坐标。
- 实际 CPU 4 线程、原生 PT FP32、CPU autocast 关闭；每次 forward 留存真实输入和后端精度证据。
- predict confidence 0.25、NMS IoU 0.7、所有类别、max_det 300；最终仅接受 class 2 且 confidence ≥ 0.45 的 car 框。不扫描阈值，不将 suitcase 等其他类别当 car。
- 使用原 crossing 93 帧及 multi 44 帧，共 137 个原始记录机会；只执行一次。空结果仍保留，异常记为 UNKNOWN 并终止，不覆盖或补跑到原目录。
- 使用独立 helper、独立 enable 收据和独立输出目录。由 root 审核源码和纯 host fixtures 后单独启用，不改第二轮 helper、输出或标签。

## 评价与判断

沿用已审评分的置信度排序、一对一 IoU 0.5 匹配、tie 处理和 portable metrics 对账，分别报告两组及各窗口 TP、FP、FN、局部额外框、其他类别重叠和实际离线耗时。中央车重选后的连续缺失机会、缺失样本跨度及前后匹配间隔是单独检查项，不能只比较总体 Precision。

全部已标注可见框都参与检测评分。crossing 的 47 帧、141 个框没有显式物理身份：仅用 frame-local GT index 匹配，已知和未知身份的 TP/FN 单列对账。只有显式非空 `physical_id` 支持跨帧逐车诊断，`proposal_id` 保留为元数据；身份未知或缺席会中断逐车缺口，不能补成假定的物理身份。multi 的 132 个框均有显式身份。

即使离线检测改善，仍须评估新增计算耗时对测量新鲜度和跟随闭环的影响。只有独立更新资源协议、冻结来源、构建，并完成同源 12 核心 / 4 安全 / 16 扩展闭环验证，才能讨论实际采用。0.60 秒观测、0.75 秒预测、歧义暂停、长丢失后显式重选的保护保持不变，正式 1000 至 1009 种子继续留出。本次离线比较不建立身份保持、飞行成功或原失败修复的结论。
