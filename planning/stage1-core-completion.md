# 阶段一核心闭环补齐记录

用户已授权持续完成阶段一。本轮纠正此前将 ROS 受控消息测试和 PX4 transport 测试等同完整飞行闭环的验收错误。

## 验收依据

真正运行的闭环必须为机载 RGB-D → YOLO11 → 三维投影 → 动态 TF → KF → 跟随控制 → PX4 Offboard → 飞行器运动 → 新图像。不能在线读取目标真值、注入观测或用静态相机代替机载相机。

- 行人、汽车分别执行唯一实例模式的真实视觉飞行。
- PX4 实际解锁、进入 Offboard、起飞；记录位置变化和状态。
- 持续有效检测与深度、世界坐标估计、跟随误差及端到端延迟有记录。
- 真实传感器链路中断测试验证短时预测与长时悬停，明确故障注入方式。
- 速度/位置模式只启用一个；失效 setpoint 不得隐含原点位置命令。
- 保留失败运行、日志、rosbag、图像/视频与评价脚本。

## 已知未知与实施决定

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 几何代理不在预训练检测器的可识别分布 | 旧 Gazebo 图像中 YOLO11n 检测为零 | 固定版本公开人/车模型，记录来源与许可，独立渲染验证 |
| 原生 x500_depth RGB/Depth 并非同投影图像 | OakD 的 RGB/Depth 分辨率、HFOV 不同 | 复用 x500 物理模型，使用单个对齐 rgbd_camera |
| 预测时钟与延迟观测冲突 | 预测推进处理时间、5 Hz 检测与 50 Hz 预测可能冲突 | 观测时域与输出预测分离，按秒限制预测 |
| 无真实起飞任务接管 | adapter 仅发心跳和转发命令 | 单命令源飞行 supervisor：预流、解锁/Offboard、起飞、接管 |
| PX4 未使用字段默认零 | 失效分支未清空 position | 未使用 setpoint 字段全部 NaN，零速度悬停 |
| 实际系统与原冻结环境不同 | 已安装 Ubuntu24.04/Jazzy/Harmonic/PX4v1.17 | 报告实际验证组合，不宣称 Humble 已验证 |

## 协作边界

目标资产、PX4机载世界与任务接管、估计器时序分别独立修改；主代理处理检测同步、PX4 setpoint 安全和实验记录，统一运行主 ROS/Gazebo 图。资产测试使用独立 partition/domain。

完成状态只由实际端到端运行证据决定，单元测试、消息连通或模型加载成功不能替代飞行闭环。

## 最终结果

阶段一工程闭环验收已完成。`stage1_final_v2` 的行人/汽车 × 速度/位置四条件全部通过：真实机载 RGB-D 与 YOLO 驱动同一 Gazebo 世界中的 PX4 飞行器，完成短遮挡同身份恢复、长丢失制动悬停，以及显式重选后持续跟随至记录结束。每组重选后状态与控制证据均超过 11 s；未以瞬间恢复代替持续跟随。

最终四个 ROS 软件包构建成功，133 项验证测试与 compileall 通过。原始日志、rosbag、机载视频、运行配置和源码哈希均已归档；历史失败及其严格规则重评结果保留。

证据见[阶段一验收记录](../docs/STAGE1_ACCEPTANCE.md)、[最终四条件报告](../results/stage1_final_v2_report.json)、[构建日志](../results/stage1_final_validation/colcon_build.log)和[验证日志](../results/stage1_final_validation/verification.log)。最终环境清单位于 `results/stage1_final_validation/environment_manifest.json`，为最终环境的事后采集记录，采集时间保留在文件内。
