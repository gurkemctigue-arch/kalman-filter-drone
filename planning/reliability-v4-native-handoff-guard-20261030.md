# 原生起飞交接的保守等待候选修复

记录时间：2026-10-30（北京时间）。这是开发候选决策，尚非验证通过或正式研究登记。

## 原证据与边界

Humble25 canonical core12 的 `car_stage1_velocity_seed004` 原终态为 FAIL，基础设施正常。独立原生起飞评价的回溯窗口为16.500至17.500源秒；首点位置误差0.18004234844133937米，超过原0.18米门限，之后20点通过。首点速度0.08984286317142322米/秒，满足原0.20米/秒门限。原判决与冻结评价源码一致，不覆盖、不翻转。

在线实际起飞锚点来自4.644秒里程计；独立评价按原录制因果合同选择的锚点与它相距约0.24578毫米。在线17.500秒的两路物理检查通过，但现有小日志没有保存16.500秒实际回调缓存及稳定计时起点。锚点差异已证实；它是否是唯一失效原因仍未证明。

## 选择的候选修改

新增独立在线参数 `native_handoff_guard_s=0.25` 源秒。保持 `native_settle_s=1.0` 不变；原两路位置、速度、时效和姿态就绪条件连续满足1.25源秒后，才进入请求Offboard阶段。任意检查失效均清零，实际模式请求前仍核原双源条件。40源秒和180墙钟秒的原起飞上限不变。

0.25秒是20 Hz监管器的五个名义检查周期，作为预先明确的工程保守余量；它不是从42微米超限量反算的最小通过参数，也不能保证覆盖任意调度延迟或长期锚点偏差。诊断增加实际稳定起点、累计时长、所需时长，继续保留输入时间戳。

独立离线评价源码、0.18米/0.20米每秒/连续1.0秒合同均保持原字节。仅增加 `native_settle_s` 会同步向前扩展离线窗口，且违反原配置登记，所以不采用。改为评价在线声明锚点会改变独立评价目标定义及因果合同，本次不采用。

## 验证顺序

1. 轻量回归覆盖累计1.0和1.249秒禁止交接、1.25秒允许交接、两路任一失效清零、源时钟与墙钟超时、原模式请求前双源检查以及非法参数拒绝。
2. 当前Humble25完整批次继续执行，所有原始终态保留；不将候选代码注入运行中的冻结根。
3. 独立复核修改，发布新来源与真实测试回执；Humble26重新构建、核实际导入/消息、完整测试，再依次完成两类clean、12核心、4安全和16扩展。同源验证通过前不消费正式1000至1009种子。
4. 若新独立评价仍失败，保留失败并诊断实际窗口；不增加容差、不缩短窗口、不挑选跨版本成功槽。

本候选只处理起飞交接的边界风险，不以其回归通过替代汽车跟随、主动云台、身份覆盖或正式多种子统计。
