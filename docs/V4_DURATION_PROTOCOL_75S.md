# v4 前瞻75秒任务协议（2026-10-30）

下一版12格核心开发及120个正式核心槽，与16格扩展开发及160个正式扩展槽，统一采用75秒 FOLLOW。本次时长改动本身不登记阈值；随后项目单独采纳了[工程要求决策](../planning/reliability-v4-engineering-requirements-decision-20261030.md)，将导航数值门标为 `REGISTERED`：距离/高度RMSE上限1.0/0.4米，导航/真值/物理身份覆盖下限0.80/0.99/0.80，并要求末端持续稳定；本机[采纳回执](../results/development_20261030/numerical_gates_adoption01.json)保存此次独立登记。两份整体实验协议仍为 `DRAFT_NOT_FROZEN_NOT_EXECUTED`，正式实验仍0/280；数值登记不替代最终同源开发、定标、协议封存及实际容量准入，也不授权正式运行。时长变化不是算法修复或性能提升。

原计划短/长遮挡及其前后各1秒的身份评估保护区、FOLLOW后32秒起的显式重选、完整 REQUEST 到记录末尾的10 Hz身份分母、所有UNKNOWN和末端稳定要求均保留。理想计划事件约占10.3秒结构性无法确认身份的时间；按现已单独采纳的80%身份覆盖门作近似预算，45秒只允许9秒UNKNOWN，即便理想执行也不足，75秒则允许15秒，约留4.7秒给确认、记录尾段和偶发缺证。真实格数仍按原锚点与完整记录计算；这只是任务可行性预算，不是实测覆盖或通过保证，80%的独立工程需求依据见上述决策，不由历史约76%的开发成绩反推。

核心和扩展同时改为75秒，保持原同类别、同种子的等时长配对定义。所有旧45秒及Humble22诊断的原参数、结果、失败和容量记录保持不变，不修改旧计划，不把跨时长比较解释为算法提升。原观测/预测时效、马氏距离门、长丢失锁存、失效悬停、禁止自动换目标和评价分母均未改动。

75秒容量必须用最终同源12核心加16扩展开发的真实逐格大小重新预算；容量组装器拒绝用45秒格替代。原45秒容量、20秒clean或线性时长外推只可作历史参考，不能成为新正式准入。每个物理卷仍需完整剩余持久化、构建/交付及原临时裕量；空间不足时先依据实测做可核验的无损优化或归档，保留原证据，再由正式准入检查实际宿主空闲。此前基于45秒任务的工期估计也须由75秒端到端吞吐更新。

静态场景检查：八个核心世界的地面视觉/碰撞平面均为200×200米，中心在原点。预设最大基础速度0.55 m/s在75秒内的单目标路程上界为41.25米；多目标一次换道的最大横向位移为8.4米，用前向与横向路程之和界定总路程不超过49.65米。最远目标初始x为23米、横向绝对值4.2米，因而目标中心保守范围不超过x=72.65米、|y|=53.85米，未见明显地面边缘风险。此检查只核预设轨迹范围，不证明Gazebo实际路径、无人机跟随或75秒性能通过；后续仍须核独立真值、实际轨迹和末端稳定。单目标50秒周期路径会进入下一周期，也须在新75秒任务中实际验证。
