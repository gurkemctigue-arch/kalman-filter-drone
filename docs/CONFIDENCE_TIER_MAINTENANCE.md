# 汽车弱检测的轨迹维护

## 失败来源

Humble50 开发核心批次已完整终态：12 场中 11 PASS、1 FAIL。失败场为
`car_stage3_multi_active_seed004`，没有基础设施停止。原始失败、录制和评价均保留。
正式 280 场尚未开始。

短遮挡前最后一次目标表面测量来自 30.6 秒。原冻结模型对同一录包的原始 RGB
再次推理，在 31.0、31.1、31.2 秒分别产生置信度约 0.413、0.342、0.380 的目标框。
原运行阈值 0.45 过滤了这些框，31.3 秒的下一次高置信度结果到达时，旧目标已经
超出 0.75 秒预测期并进入不可自动复活的 LOST 状态。退出 LOST 必须显式重选。

31.0、31.2 秒的原始深度及同采集时刻记录的 TF 通过了原有**表面测量**支持检查。
31.1 秒缺少相应记录，保持未评价。这些离线复核不能替代轨迹关联、全像素导航
可见性检查或新飞行验收，也没有使用带文字覆盖的视频作为推理输入。

另有独立的早期导航拒绝：27.9–28.8 秒的
`exclusive_visibility_unexplained_foreground`。该段表面轨迹仍连续关联。完整像素
复核在 28.0、28.4 秒分别定位到 2、8 个约 15 米深的相邻车边缘像素，它们落在
相邻车检测框外，进入了约 6.9 米远的被选车辆测量区。原保护合理，继续保留。
500 点表面采样恰好漏过这些像素，不能替代完整导航检查。31.0 秒弱框同样被一个
外来像素拒绝；31.2 秒弱框通过原完整导航参考几何检查，仍不等于完整闭环通过。

## 实现约束

汽车三阶段配置使用两项置信度阈值：初始化为 0.45，维护为 0.25。行人保留原配置。
两个 `TargetManager` 参数同时为 `None` 时保留旧 API 行为；ROS 参数 -1 表示禁用。

- 高置信度检测可以按原确认规则建立轨迹和初始化任务。
- 弱检测只能维护已有、已确认或短时预测中的三维轨迹。它必须通过距离和马氏距离
  两项关联门；IoU 或 legacy 关联方式不能绕过这些门。
- 启用汽车表面恢复合同后，弱检测还必须有当前采集的明确表面支持。漏传支持标志
  不作为支持。
- 所有可行高低置信度边共同参与歧义判断。涉及弱检测的多解关联分量进入歧义，
  不按置信度先抢占，也不按最近目标自动选择。
- 弱检测不能出生、确认新轨迹、自动初始化任务或兑现初始选框/重选。
- 显式框选只有在当前高置信度证据验证后才改变任务身份。弱框、空帧和越界请求
  不能清除现有 UUID 或 LOST 重选锁。

检测诊断记录每框 `maintenance_only` 及两项阈值，实际运行参数 YAML 也保留阈值。
测试脚本的候选计数、左右/中位选择和重选使用同一高置信度候选池。

观测最大年龄仍为 0.60 秒，预测期限仍为 0.75 秒。导航几何、PX4 安全限制及
禁止自动切换目标的规则保持原数值。此实现为带两项置信度阈值的保守关联扩展，
不代表完整 ByteTrack 或 ReID。

## 验证范围

核心关联、ROS 适配器和脚本入口有独立测试。小型假模型输出验证接口行为，原始
图像复核验证失败原因；两者均不能代替新版本的原生构建和完整核心 12 场闭环实验。
新版本必须独立冻结、构建、验证并运行全部 12 场，不能拼接 Humble50 的 11 个 PASS。
全部核心场景通过且证据完整后才进入安全 4 场及后续扩展、正式重复研究。
