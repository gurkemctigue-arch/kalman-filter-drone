# 基于 YOLO11 与卡尔曼滤波的 RGB-D 云台相机无人机目标跟踪与自主跟随系统设计及仿真研究

## 一、课题概述

本课题面向仿真环境，设计一套可迁移到真实无人机的视觉目标跟踪与自主跟随系统。系统使用 RGB-D 相机获取彩色图像和深度信息，使用 YOLO11 完成行人与汽车检测，通过二维候选关联、三维坐标变换和卡尔曼滤波获得目标位置与速度，随后由无人机外环控制器生成 PX4 Offboard 设定值。首版核心关联采用可复现的 IoU 与三维门控方法；ByteTrack、外观 ReID 和长时重识别不作为首版前置依赖。

系统设置唯一实例和指定个体两种运行模式。唯一实例模式要求场景中只有一个符合条件的目标；指定个体模式在任务开始时由用户或测试脚本选定目标框，系统在多个同类目标中保持该目标身份。短时遮挡使用运动预测处理，长时间丢失后进入悬停并重新选框。完整外观重识别（ReID）作为后续研究方向，不作为第一版核心验收条件。

## 二、研究目标

1. 以实际锁定的 Ubuntu 24.04.1、ROS 2 Jazzy、PX4 v1.17.0、Gazebo Harmonic 和 uXRCE-DDS 作为仿真基线，在 WSL2 中验证机载 RGB-D 驱动的真实视觉飞行闭环；版本变化须记录，不能在实验中无记录漂移。
2. 实现行人和汽车的 RGB-D 检测、深度测量、三维投影和世界坐标变换。
3. 实现状态为 `[x, y, z, vx, vy, vz]` 的三维匀速卡尔曼滤波器，支持自适应观测噪声和马氏距离门控。
4. 实现唯一实例和指定个体两种目标管理模式，禁止目标丢失后自动切换到其他同类目标。
5. 实现速度设定值和位置设定值两种可切换的 PX4 外环控制模式，同一时刻只启用一种模式。
6. 实现三轴云台仿真接口，其中 yaw 和 pitch 用于视线跟踪，roll 用于保持画面水平。
7. 通过预注册的独立飞行和录制输入配对重放，对比原始测量、EMA、固定观测噪声 KF 和自适应 KF；分别报告实际闭环效果、状态估计误差、覆盖率和全部失败，不能用离线重放推断控制改善。

## 三、系统总体架构

```text
RGB-D 相机
    ↓
YOLO11 检测器
    ↓ TargetObservationArray（完整检测帧，含空帧）
深度 ROI 统计与三维反投影
    ↓
TF 时间同步与局部世界坐标变换
    ↓
二维/三维轨迹关联、目标管理与三维卡尔曼滤波
    ↑ TargetSelection（用户/测试脚本选框）
    ↓ TargetState
FollowController
    ↓ TrackingCommand
仿真飞行任务接管与失效保护
    ↓
PX4 Offboard 适配器 ──→ PX4 SITL ──→ 新机载图像

阶段三：三轴云台适配器协同控制相机姿态
```

算法层不直接依赖 Gazebo、PX4 或真实硬件类型。Gazebo、PX4、真实相机和真实云台通过适配器接入。运行时禁止使用 Gazebo 实体名称或真值 ID 参与目标关联，真值仅用于离线评价。

## 四、核心模块设计

### 4.1 检测与深度测量

- YOLO11 首版使用预训练模型，类别参数可配置为 `person` 或 `car`；两类目标分别完成同一套实验和验收，混合类别同时跟踪属于后续扩展。
- 每个候选发布类别、置信度、边界框、时间戳和图像帧号。
- 深度值从边界框收缩 ROI 中提取，使用有效深度中位数。
- 记录有效像素比例、深度标准差、最小值和最大值。
- 深度无效、过期或有效率不足时，不生成有效三维观测。
- 深度无效时允许二维框暂时维持关联，但状态只能进入 `PREDICTED`，不能把二维框刷新时间当作三维测量时间；超过预测时限后进入 `LOST`。

### 4.2 三维投影与坐标系

使用相机内参将像素和深度反投影到 `camera_optical_frame`，再通过带时间戳的 TF 变换到 `map` 或 `odom`。卡尔曼滤波在稳定的局部世界坐标系中运行，避免无人机平移、旋转和云台运动被误认为目标速度。

ROS ENU/FLU 与 PX4 NED/FRD 的转换只允许发生在 PX4 适配器中。所有观测、TF、云台角度和无人机里程计保留采集时间戳；仿真统一使用 `/clock` 和 `use_sim_time`。

### 4.3 目标管理

目标轨迹 ID 与任务目标 ID 在设计上分开管理：

- `track_id`：二维跟踪器当前轨迹编号，可因轨迹重建而改变；
- `target_uuid`：任务开始时选定的任务目标身份。核心会在选定时生成或接受该 UUID，短时轨迹重建不改变它；轨迹被移除后的稳定 UUID 重绑定仍需要后续 ReID/更完整关联模块，长时丢失默认重新选框。

唯一实例模式只在存在一个 confirmed 候选时自动锁定；锁定前后出现多个候选均进入 `ambiguous` 并悬停，输出预测不能解除歧义。指定个体模式通过 `TargetSelection` 初始化，后续仅接受运动、框重叠和深度位置一致的关联结果。目标状态包括 `tentative`、`confirmed`、`coasting`、`lost` 和 `removed`。ROS 仿真按采集时间与最后有效三维观测执行秒级生命周期：默认 0.75 秒内预测，超时锁存丢失，3 秒保留诊断轨迹；迟到帧不能解除丢失，须显式重新选框或重置任务。便携核心同时保留供其他调用者使用的帧数参数。

### 4.4 卡尔曼滤波

状态向量为：

```text
x = [px, py, pz, vx, vy, vz]^T
```

状态转移采用三维匀速模型，过程噪声采用白噪声加速度模型。观测噪声根据检测置信度、深度有效率和深度离散度自适应放大。使用三维马氏距离门控拒绝异常测量。短时缺测只执行预测；预测时间超过阈值后转为 `lost`，控制器进入悬停或失效状态。核心过滤器本身不拥有 ROS 时钟，秒级阈值由上层节点依据观测时间戳执行，不能只依赖回调次数。

### 4.5 跟随控制

FollowController 是 PX4 外环控制器，不直接输出姿态、电机或推力命令。它支持：

- 速度模式：输出局部世界系速度和偏航速度；
- 位置模式：输出期望位置和偏航设定值；
- 速度、加速度、死区、积分限幅和目标过期保护；
- 目标无效、车辆无效、坐标系不一致时输出明确的 hold/failsafe。

速度模式作为默认主实验模式，位置模式作为可切换对照模式。两者不能同时发布给 PX4。

### 4.6 三轴云台

- yaw：水平视线控制；
- pitch：垂直视线控制；
- roll：画面水平稳定；
- 所有角度、角速度、限位和反馈时间戳均参数化。

第一阶段锁定云台中位，第三阶段再启用主动云台。无人机根据世界坐标中的目标相对位置跟随，云台负责快速保持视线，二者不共同对同一个图像中心误差进行控制。

三轴使用真实可动关节和编码器反馈；相机动态 TF 必须在原图像采集时刻查询。云台命令角不能冒充实际角度。机体慢速偏航回正，避免 yaw 长期触及限位；云台反馈过期时停止主动补偿。

## 五、分阶段实施路线

### 阶段一：单目标状态估计与闭环

完成唯一实例模式下的行人和汽车仿真闭环，包括 RGB-D 观测、三维投影、卡尔曼滤波、PX4 外环跟随、短时遮挡预测和目标丢失悬停。

### 阶段二：多同类目标指定个体

场景中加入 2 至 3 个行人或汽车。任务开始时由用户或测试脚本选框，系统维护全部轨迹但只控制指定目标。通过独立物理身份评价和实际飞行，验证平行运动、深度分离的图像交叉、短遮挡和长丢失重选。多个候选同时满足门控条件时暂停跟随；歧义超过预测时限后锁存丢失，不自动换目标。

### 阶段三：三轴云台协同

启用三轴云台仿真模型，完成 yaw/pitch 视线控制和 roll 水平稳定，研究云台快环与无人机慢环之间的分工、延迟、限位和回中策略。

## 六、实验设计

实验轨迹包括直线、转弯、加速和减速。环境逐步加入深度噪声、深度空洞、检测丢帧、推理延迟、消息延迟和目标遮挡。多目标实验加入同类目标交叉。

主线基线为：

1. YOLO 逐帧检测与原始三维测量；
2. YOLO 加 EMA 或 α-β 滤波；
3. YOLO 加固定参数卡尔曼滤波；
4. YOLO 加自适应观测噪声卡尔曼滤波。

在线研究采用每类、每方法至少 10 个随机种子：两类别 × 四方法 × 十种子的速度控制主矩阵共 80 次独立飞行；另有两类别 × 十种子的自适应 KF 位置控制兼容矩阵，共 20 次。四方法使用相同安全门控和关联观察器，仅改变真正送入控制器的状态估计输出。原始测量与 EMA 不外推位置，速度由相邻采集时刻差分得到；其协方差是明确声明的启发式量。

阶段二交叉场景两类别各 10 次；另有两类别的平行遮挡、歧义悬停、唯一实例多候选安全测试共 6 次。阶段三两类别 × 中位/主动模式 × 十种子，共 40 次配对飞行。另做两类别的多目标与主动云台联合工程验证。各矩阵串行执行，失败保留且不得同名重跑替换。

同一录制输入的滤波重放采用四份真实 RGB-D 飞行录制。每份原始输入只评价一次，噪声、空洞、丢帧、延迟及组合扰动分别使用 10 个种子；四方法共享同一次生成的扰动序列，共 816 条方法记录。这些记录不能计为独立闭环飞行。加减速和不同距离另做工程覆盖，不把少量录制夸大为十次独立飞行。

报告均值、样本标准差、配对 bootstrap 95% 区间及 Wilson 失败率区间。失败和证据缺失留在分母，不把缺失误差填为零，不把每帧当独立样本；可测量配对与双方成功的条件配对分开。Precision、Recall、mAP 使用独立网格投影并逐图审核的无遮挡、完整入画静态仿真子集，不能推广为真实环境精度。

三维误差分别报告理想真值飞行器位姿重放和实际 PX4/TF 在线输出。深度 ROI 对应可见表面，不能直接与模型中心比较。表面锚点仅用独立训练段校准，之后冻结；局部地图到世界的对齐仅用开头固定时段的无人机状态，并报告其后留出段误差，不能用目标误差反向拟合坐标。

指定个体评价以初始选框请求和同一源图像时刻的独立真值确定预期物体。已知正确、已知错误、几何重叠无法判定、无新鲜检测分别统计；UUID 不变不证明物理身份正确。HOTA、IDF1、ID Switch 按任务分段，明确完整投影框诊断与无遮挡几何子集的范围。第一版的“重捕获”只指短失联恢复，长失联后的显式重新选择另报耗时与成功率，不称自动 ReID。

指标分为四类：

- 检测：Precision、Recall、mAP、FPS、端到端延迟；
- 状态估计：三维位置 RMSE、速度 RMSE、遮挡预测误差、95% 误差分位数；
- 跟随控制：距离误差、高度误差、画面中心误差、超调量、稳定时间、控制抖动；
- 身份保持：目标保持率、ID Switch、IDF1、HOTA、指定目标重捕获率和重捕获时间。

## 七、验收标准与交付物

工程验收包括：版本可复现、消息接口可构建、坐标和时间戳测试通过、行人与汽车唯一实例闭环跑通、指定个体首帧选框和短时遮挡不切换、长时丢失悬停并重新选框、速度/位置模式可切换、云台中位和三轴控制接口可运行。当前验收不把轨迹重建后的自动 `target_uuid` 重绑定或完整 ReID 作为必需项。

研究验收按预先固定的实验矩阵报告结果，允许卡尔曼滤波在某些条件下没有显著改善，但不得事后删除失败样本或修改实验条件。

交付物包括：

- Python 核心算法包；
- ROS 2 接口、检测器、状态估计器、控制器和 PX4 适配器；
- 参数文件、启动文件和版本锁定文件；
- Gazebo 世界、目标轨迹和传感器配置；
- 模型权重说明、rosbag、评价脚本和原始结果；
- 仿真演示视频和最终论文/计划书。

## 八、明确边界

第一版不承诺长时间离开视野后的自动 ReID、任意开放环境搜索、自动避障和真实无人机飞行验证。后续可在当前接口基础上增加完整 ReID、更多车辆和物体类别、主动搜索以及真实机适配。

## 九、实现与验证记录

工程已进入真实视觉 SITL 验证。当前实际环境为 Ubuntu 24.04.1 WSL2、ROS 2 Jazzy、Gazebo Harmonic、PX4 v1.17.0、同分支 px4_msgs 与 Micro XRCE-DDS Agent v2.4.3；精确版本及资源哈希见 `VERSION_LOCK.md` 和环境清单。原先计划的 Ubuntu 22.04/Humble 组合仍需另行复现，不能将本次结果视作该组合的验证。

在当前笔记本 CPU 与软件渲染环境中，重复研究资源固定为请求仿真速度 0.5 倍、行人 YOLO11n/320/2 线程、汽车 YOLO11s/640/4 线程。0.7 倍预试验配置及失败记录保留，不纳入新的正式重复矩阵。仿真时间的 0.75 秒失联和 0.60 秒输入新鲜度限制不放宽；同时保留实际耗时、推理时延和达到的仿真速度。这些试验不能证明真实时间中的实时性能，未来移植必须重新验证传感器标定、定位、算力与执行时序。

单个 Gazebo 世界已经包含真实 PX4 x500 动力学、机载对齐 RGB-D 和行人或汽车。在线管线只使用传感器与 PX4 状态，Gazebo 模型真值仅供 rosbag 离线评价。已提供飞行任务接管、速度/位置模式、秒级丢失门控、动态 TF、渲染遮挡与显式重新选框接口。

三阶段逐项结果以阶段验收文档、统一 HTML 验收总览和原始报告为准；本计划书描述设计与评价约定，不代替验收记录。历史受控消息测试与 transport 测试保留，作为组件验证。统计矩阵未执行的项必须保持未完成，不能从一轮成功飞行推导全场景成功。
