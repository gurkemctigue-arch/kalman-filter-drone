# 查看与复核成果

当前正式研究为 `v3`，冻结 Linux 环境的 531 项测试、四个 ROS 包构建与导入路径隔离均已通过。166 个主飞行槽均已终态（107 PASS、58 FAIL、1 INTERRUPTED），主离线台账覆盖 166 个槽，另列 16 项工程扩展和 16 项补充后处理也已完成终态登记。失败、证据不完整和不适用项均保留；这些计数不是算法成功率。结果工件不随公开源码提交，归档边界见 [结果工件说明](RESULTS_ARTIFACTS.md)。构建和单元测试通过不表示正式试验全部通过；完整结论见本地最终报告。

旧 `v1` 的 8 次正式尝试按原评价仍为 7 PASS、1 FAIL，v1/v2 原计划、录制、报告和失败全部保留，不计入 v3 的 166 次分母。评价修订 3 对原汽车 raw bag 的独立核对为 PASS，报告与 SHA 审计另存；原始 FAIL 和修订 2 FAIL 均不覆盖，详见 [评价修订 3](EVALUATION_REVISION_3.md)。

在本机最终归档中，先双击打开 `results/frozen_fullplan_v3/交付入口.html`，可集中查看 8 段视频、研究报告、最终计划书及逐次验收。完整逐次结果入口为同目录的 `验收总览.html`。这些页面是本地静态文件，不随公开源码提交；完成状态以对应原始清单和评价 JSON 为准。

页面支持读取研究目录中与 `plan.json` 同级的 `superseded.json`，只有其 `plan_sha256` 与该计划匹配时才采用历史替代说明；绑定不匹配会显示清单问题。若本地归档包含 `results/frozen_fullplan_v1/full_plan_research_v1/superseded.json`，它可能仍显示当时登记的 fullplan_v2 后继名称，同时保留 v1 原来的 7 PASS、1 FAIL 和 158 PENDING。该历史标识不改写原判定，不自动说明 v2/v3 当前完成度；当前研究须查看 v3 自身清单。

先看研究矩阵中的完整分母，再按阶段浏览逐次录制。主研究 166 次与额外 16 次工程扩展分别统计；飞行、离线分析、工程安全 PASS 是三个不同结果。历史失败和未执行项都应可见。每帧或离线重放不计为独立飞行重复。

## 看视频时检查什么

- 阶段一：机载画面中出现行人或汽车；起飞后开始跟随；遮挡时允许短时预测，持续丢失后进入 HOLD；显式重选后才再次跟随。
- 阶段二：画面中有多个同类目标，黄色 `SELECTED` 框标出当前指定轨迹。控制器只使用指定目标，丢失后不会自行选择旁边的目标。任务 UUID 与轨迹编号不同；编号稳定本身不证明物理身份正确。
- 阶段三：查看主动云台与中位录制，画面中显示实测 Y/P/R。原始编码器、动态 TF 和独立物理连杆验证见云台报告，不能只看命令角或中心误差就认定三轴运动有效。

视频上的检测框属于预览叠加，可能稍晚于原始画面。需要严格判断交叉目标身份时，打开该录制的 `identity_review/` 源图接触表及 `physical_identity.json`；接触表按原始采集时间配对。视频的播放时间也不能替代画面仿真时间或原始时间戳。

## 看报告时检查什么

1. 工程评价中的所有检查项及整个录制区间。长失联后的悬停安全，不等于完成了短遮挡测试；末尾一次成功也不能抵消中途失败。
2. 身份评价同时看 CORRECT、WRONG、UNKNOWN、无新鲜所选检测及完整任务机会分母。UNKNOWN 不能算正确；抽样目视检查不能批准整段身份标签。
3. 状态估计误差区分可见表面锚点与模型中心，区分实际 PX4/TF 在线输出与使用理想真值位姿的离线重放。
4. 距离、高度、画面中心与覆盖率一起看。稳定时间为空且标 `right-censored` 表示观察窗口内未持续稳定，不能写成 0 秒。图像到首次跟踪命令的延迟止于控制发布，不含 PX4 执行器响应。
5. 配对结果按整次飞行和同一 seed 比较。全可测量配对与双方 PASS 的条件配对分开；先看失败率，再解释误差及置信区间。

car position seed08 的原 FAIL 是已确认的评价基础设施/证据异常：[独立审计](V3_BAG_INFRASTRUCTURE_AUDIT.md)发现压缩帧未正常结束，ROS 原生解压少输出末尾 128 KiB，而独立解码的 SQLite 完整。正式原始记录没有被诊断产物替换，也没有改判为 PASS；压缩为何未结束仍未知。查看失败分母时保留该槽，但不能把它当成完整可评分的算法性能样本，或把其他全部 FAIL 归为相同原因。

当前复现环境是 Ubuntu 24.04.1 WSL2、ROS 2 Jazzy、PX4 v1.17.0、Gazebo Harmonic。原 Ubuntu 22.04/Humble 组合和实机飞行没有因此被验证。研究请求 RTF=0.5，不能据此声称墙钟实时运行。

## 更新页面

在项目目录执行：

```powershell
python scripts/build_acceptance_dashboard.py --results-dir results --additional-results-dir results/frozen_fullplan_v3 --output results/验收总览.html
```

该命令只读取已有小报告并生成页面，不启动仿真、不重跑失败试验。正式批次运行与恢复见 [研究运行说明](FULL_PLAN_RESEARCH_RUNBOOK.md)。不要在飞行期间运行离线 YOLO、解压 bag、批量复制或重型绘图。
