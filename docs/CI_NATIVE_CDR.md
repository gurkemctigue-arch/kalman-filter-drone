# 便携测试与真实 ROS 消息序列化测试的环境边界

GitHub Actions 的便携任务使用 Ubuntu 22.04 和 Python 3.10/3.12，安装便携包及测试依赖，不安装 ROS，也不执行 colcon build。完整原生验证另在已配置的 Humble 环境中执行，包含真实生成消息、类型支持和 CDR 往返。

2026-11-02，提交`d4e473a`的两个 Actions 任务各运行1819项检查，均为1项失败、5项跳过。唯一失败来自真实CDR测试在无ROS环境导入`rclpy`；依赖安装成功，后续replay步骤因前面失败而跳过。原始失败和日志片段见[诊断证据](../tools/diagnostics/portable_cdr_ci_boundary01/README.md)，没有将这次失败解释为飞行或算法失败。

修复保留现有CDR测试的全部消息字段、路径、类型支持和序列化断言，在原来的新Python子进程中检查顶层`rclpy`及`uav_tracking_interfaces`包是否确实不存在。只有未登记原生运行配置、缺少包、子进程返回专用退出码77且输出精确缺包标记时，才将这一项记为SKIP。

| 环境或异常 | CDR测试行为 |
| --- | --- |
| Windows | 保留原有精确平台跳过 |
| Linux便携环境，明确缺少ROS或生成接口包 | 仅该真实CDR项跳过，原因保留 |
| Linux具备真实ROS和生成接口 | 执行原CDR测试及全部断言 |
| 已登记`UAV_TRACKING_DDS_RUNTIME_CONFIG`却缺少依赖 | 失败，不允许缺包跳过 |
| 包存在，但导入、类型支持、路径或序列化损坏 | 原异常或断言失败，不捕获为SKIP |

Windows上的边界观察仅临时绕过现有方法的平台装饰器：可选依赖缺失时实际跳过；加上原生必需标志后，相同缺包实际失败。观察结束恢复了环境和方法。这两次观察不是Linux验证，也不是成功的真实CDR往返。具体Linux便携测试结果应读取对应Actions原始日志；原生验收仍需真实构建、CDR及完整套件。

本修复更新公开main的测试环境选择。当前实验仍使用独立冻结的`5aa188f`来源；实际core核验从`frozen_root`逐项读取文件，未改写运行中的测试副本或原合同。现行final-v2准备工具也从该冻结目录复制，不会自动混入公开main补丁。最终实验来源以对应whole-source封存记录为准；公开便携CI通过不代替该来源的原生验证。
