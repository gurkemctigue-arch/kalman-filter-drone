# 遮挡刺激的请求、响应与保持时间

`scripts/stage1_flight_monitor.py` 的实验遮挡板按顺序执行两个刺激：进入
FOLLOW 后第 12 秒启动短遮挡，第 25 秒启动长遮挡。前一次刺激尚未收到
开启响应时，后一次不会发出关闭请求。

每次刺激依次经过 `waiting → closing → holding → opening → complete`。
保持时间从**本次关闭请求对应的成功服务响应被 monitor 收到时**开始，
而不是从预定时刻或请求发出时开始。默认短遮挡保持至少 0.20 + 0.05 秒，
长遮挡至少 3.00 + 0.05 秒；0.05 秒是行人和汽车共用的固定渲染余量。
timer 调度或尚未完成的云台位置刷新可能延后开启，但不会提前开启。

服务响应不是相机实际遮挡起止时间。日志保持以下区别：

| 事件 | 含义 |
| --- | --- |
| `shutter` | 遮挡板关闭或开启的服务请求；不是已执行声明 |
| `shutter_service_result` | 与 `request_id` 精确关联的服务结果和收到响应的仿真时间 |
| `shutter_hold_started` | 关闭成功后计算出的最早允许开启时间 |
| `shutter_hold_finished` | 收到开启成功响应后的本次调度记录 |
| `shutter_pose_update` / `shutter_pose_update_result` | 云台运动时按实测相机 TF 更新位置；不创建新遮挡窗口，也不重置关闭计时 |
| `shutter_schedule_failure` | 某次关闭或开启失败，保留原失败结果 |

服务失败后最多发送一次带 `cleanup=true` 的开启请求以停放遮挡板；即使
清理成功，也不把原实验动作改为成功。未就绪的服务和未完成的响应都不能
作为已完成遮挡的证据。`summary.json` 的 `occlusion_schedule` 保留每次
刺激的状态、请求 ID、ACK 时间与开启下限。

离线 evaluator 仍要求真实检测器中断、预测、短时身份保持和长时丢失后的
悬停与显式重选证据；本修复不生成空检测、不读取目标真值，也不改变
0.60 秒输入新鲜度和 0.75 秒最大预测期限。evaluator 中的请求窗口仍是
请求窗口，不能称为精确渲染遮挡时长。异常迟到的关闭响应可能使请求窗口
超过短遮挡界限，该试验应按现有严格规则评价，不能通过修改标签使其通过。

回归：`tests/test_shutter_timing.py` 覆盖迟到 ACK、提前开启保护、关闭失败、
异常响应、同步请求异常、开启失败与一次性清理、下一刺激串行化、云台刷新
ACK 隔离以及服务尚未就绪的情况。真实空检测和遮挡恢复仍须由 rosbag 验证。
