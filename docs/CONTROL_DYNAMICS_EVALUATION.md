# 跟随瞬态与重选恢复评价

入口为 `scripts/evaluate_follow_dynamics.py TRIAL --target-class person|car --output TRIAL/follow_dynamics.json`。多目标试验另传 `--physical-identity-report TRIAL/physical_identity.json`。只能在飞行结束后执行，不能与 Gazebo/PX4 和在线 YOLO 争用资源。

距离与高度参考直接读取试验保存的 `configuration/runtime_parameters.yaml`；旧录制可使用对应阶段、类别的参数快照及明确的运行覆盖值。没有快照、数值无效或运行参数与实际快照冲突时拒绝推测。汽车参考距离不能凭类别猜测。

评价从实际 FOLLOW 交接到完整录制终点，使用固定 10 Hz 的独立 Gazebo 无人机与目标模型原点真值，作有时间包围的插值，不外推。多目标参考由显式 REQUEST 框与独立物理身份报告确定，并持续到下一次 REQUEST；状态消息断流不能把最差的失联尾段从距离误差中删掉。未知身份、缺失真值保留为缺测，并给出全部时间机会数、真值覆盖和有效控制覆盖。

模型原点与 RGB-D 可见表面锚点不同。模型原点高度误差不是控制器自身锚点误差或定位偏差；即使控制器正常工作，目标几何也可能使原点高度误差始终在评价带外。定位精度另外使用冻结表面锚点及独立无人机坐标验证评价。

初始瞬态窗口从 FOLLOW 到第一次遮挡请求、下一次任务选择或录制终点中最早者，窗口规则不根据观察结果选择。所有显式选择各有一个窗口，截止下一次选择或完整终点。新选择窗口只能使用该 REQUEST UUID 的有效控制；旧任务的稳定不能替代未确认的新任务。

- 超调：相对窗口第一个真值误差符号，在参考值另一侧达到的最大绝对误差，单位米。初始误差为零或缺测时方向未定义，超调保持空值。这不是静止对象阶跃响应的百分比超调。
- 距离稳定带为 `max(0.5 m, 期望距离的 10%)`，高度稳定带为 `0.25 m`。稳定时间要求在带内持续至少 3 秒，并连续保持到窗口终点。真值缺失、超过 0.15 秒证据间隙、无效控制、陈旧状态或轨迹不一致都会中断稳定段。
- 同时报告第一次连续 3 秒进入带内的时间，避免把“曾经进入”和“到终点仍稳定”混为一谈。未稳定、记录太短或后期失败时，最终稳定时间为空，并标记右删失；统计不能将其填成零，也不能仅用已稳定样本描述整体成功率。
- 显式选择到首次新鲜 MEASURED 确认的延迟单独记录。未确认请求也保留，不能当作自动 ReID、短遮挡自然恢复或跨任务 ID Switch。

状态、控制状态、任务请求和 FOLLOW 阶段使用 `max(源时间戳, 接收时的 /clock)` 表示运行时生效时间，迟到消息不能把未来控制回填到过去。真值始终按自身源时间插值。

`visual_control_metrics` 另记录检测框的画面中心误差（像素和按图像尺寸归一化）、全部检测机会与可观测比例。多目标仅使用同一源图时刻的新鲜所选轨迹框，空帧、无所选检测与歧义帧仍在机会分母；不能平均所有候选框。该指标是检测可见条件下的框中心，不能代替人工标注的物理目标中心精度。

图像至首次控制命令延迟按任务、轨迹、最后接受图像去重。预测输出的源图时间由 `state.header - prediction_age_s` 还原，防止因控制定时器恰好在 MEASURED 短暂发布之后运行而漏记第一次实际使用该图像的 PREDICT 命令。它包含估计与控制交付，但截止于控制器命令发布，不包含 PX4 执行器响应；使用仿真时钟，不能声称已证明墙钟实时性。

首个真实录制 smoke 为 `stage1_final_v2_person_velocity/follow_dynamics.json`。其全部 437 个真值机会均可匹配；初始距离稳定时间约 2.9 秒，长丢失后的显式重选距离稳定时间约 3.1 秒，测量确认约 0.12 秒。高度原点指标保持删失。这是一份录制的评价证据，不是十次重复统计。
